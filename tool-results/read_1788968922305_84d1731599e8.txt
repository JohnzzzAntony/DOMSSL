     1→# Domain & SSL Manager --- Claude Build Specification
     2→
     3→## 1. Project Objective
     4→
     5→Build a production-ready, secure web application for centralized
     6→management of domains, SSL/TLS certificates, servers, DNS providers,
     7→expiry monitoring, notifications, certificate issuance, automatic
     8→renewal, and automatic certificate installation.
     9→
    10→The application must be able to:
    11→
    12→-   Add, edit, verify, monitor, and delete domains.
    13→-   Discover and verify domain expiry dates using authoritative
    14→    domain-registration data such as RDAP and supported registrar APIs.
    15→-   Inspect the live SSL/TLS certificate served by each domain over
    16→    HTTPS.
    17→-   Compare stored dates with freshly discovered dates and clearly
    18→    identify mismatches.
    19→-   Monitor domain and SSL expiry continuously.
    20→-   Notify administrators before expiry, with 5 days being the mandatory
    21→    critical alert threshold.
    22→-   Support free publicly trusted SSL certificates through ACME
    23→    providers, primarily Let's Encrypt.
    24→-   Automatically renew certificates where automation is supported.
    25→-   Automatically install renewed certificates on supported servers.
    26→-   Support Nginx and Apache initially.
    27→-   Support SSH-based server management using secure, restricted
    28→    credentials.
    29→-   Support DNS-01 automation for supported DNS providers, initially
    30→    Cloudflare.
    31→-   Validate server configuration before reload.
    32→-   Automatically verify the live certificate after installation.
    33→-   Roll back to the previous known-good certificate/configuration if
    34→    deployment fails.
    35→-   Maintain detailed audit logs for every automated and manual
    36→    operation.
    37→
    38→The product should feel like a professional enterprise DevOps/SaaS
    39→control panel, not a generic hosting panel.
    40→
    41→------------------------------------------------------------------------
    42→
    43→# 2. Core Product Principle
    44→
    45→The application must never blindly trust manually entered expiry dates.
    46→
    47→For every domain:
    48→
    49→1.  User adds domain.
    50→2.  System performs a fresh domain-expiry lookup.
    51→3.  System connects to the live HTTPS endpoint.
    52→4.  System inspects the actual certificate.
    53→5.  System compares discovered values against stored values.
    54→6.  System displays whether the information is verified.
    55→7.  Only after successful verification should automation be enabled by
    56→    default.
    57→8.  Every check must record timestamp, source, result, and errors.
    58→
    59→Example:
    60→
    61→``` text
    62→example.com
    63→
    64→Domain expiry:
    65→RDAP              2027-02-15
    66→Registrar API      2027-02-15
    67→Stored value       2027-01-15
    68→
    69→Status:
    70→⚠ DATE MISMATCH
    71→
    72→SSL expiry:
    73→Live certificate  2026-10-30
    74→Stored value       2026-10-30
    75→
    76→Status:
    77→✓ VERIFIED
    78→```

   939→# 15. Automatic SSL Renewal Workflow
   940→
   941→The worker should implement:
   942→
   943→``` text
   944→Check certificate
   945→        ↓
   946→Days remaining <= renewal threshold?
   947→        ↓
   948→Request ACME renewal
   949→        ↓
   950→Perform validation
   951→        ↓
   952→Receive certificate
   953→        ↓
   954→Backup current certificate
   955→        ↓
   956→Install new certificate
   957→        ↓
   958→Test Nginx/Apache configuration
   959→        ↓
   960→Reload server
   961→        ↓
   962→Perform live HTTPS verification
   963→        ↓
   964→Success?
   965→   /          \
   966→ YES           NO
   967→ ↓             ↓
   968→Complete     Rollback
   969→                ↓
   970→             Alert
   971→```
   972→
   973→Use a renewal threshold such as 30 days by default, while retaining the
   974→mandatory 5-day alert.
   975→
   976→Do not wait until 5 days before starting renewal.

  1609→# 32. Security Requirements
  1610→
  1611→This is a security-sensitive application because it may control
  1612→production servers.
  1613→
  1614→Implement:
  1615→
  1616→-   Strong authentication.
  1617→-   Password hashing with Argon2id or equivalent.
  1618→-   Optional/required 2FA for privileged users.
  1619→-   Role-based access control.
  1620→-   Secure HTTP-only cookies.
  1621→-   CSRF protection where applicable.
  1622→-   Strict CORS configuration.
  1623→-   Rate limiting.
  1624→-   Input validation with Zod.
  1625→-   SQL injection protection through Prisma.
  1626→-   XSS protection.
  1627→-   Content Security Policy.
  1628→-   HSTS.
  1629→-   Secure headers.
  1630→-   Encryption at rest for credentials.
  1631→-   Secrets stored outside source code.
  1632→-   Audit logging.
  1633→-   SSH host-key verification.
  1634→-   No arbitrary shell commands from user input.
  1635→-   Command allowlisting.
  1636→-   Least-privilege server accounts.
