     1→     1→# Domain & SSL Manager --- Claude Build Specification
     2→     2→
     3→     3→## 1. Project Objective
     4→     4→
     5→     5→Build a production-ready, secure web application for centralized
     6→     6→management of domains, SSL/TLS certificates, servers, DNS providers,
     7→     7→expiry monitoring, notifications, certificate issuance, automatic
     8→     8→renewal, and automatic certificate installation.
     9→     9→
    10→    10→The application must be able to:
    11→    11→
    12→    12→-   Add, edit, verify, monitor, and delete domains.
    13→    13→-   Discover and verify domain expiry dates using authoritative
    14→    14→    domain-registration data such as RDAP and supported registrar APIs.
    15→    15→-   Inspect the live SSL/TLS certificate served by each domain over
    16→    16→    HTTPS.
    17→    17→-   Compare stored dates with freshly discovered dates and clearly
    18→    18→    identify mismatches.
    19→    19→-   Monitor domain and SSL expiry continuously.
    20→    20→-   Notify administrators before expiry, with 5 days being the mandatory
    21→    21→    critical alert threshold.
    22→    22→-   Support free publicly trusted SSL certificates through ACME
    23→    23→    providers, primarily Let's Encrypt.
    24→    24→-   Automatically renew certificates where automation is supported.
    25→    25→-   Automatically install renewed certificates on supported servers.
    26→    26→-   Support Nginx and Apache initially.
    27→    27→-   Support SSH-based server management using secure, restricted
    28→    28→    credentials.
    29→    29→-   Support DNS-01 automation for supported DNS providers, initially
    30→    30→    Cloudflare.
    31→    31→-   Validate server configuration before reload.
    32→    32→-   Automatically verify the live certificate after installation.
    33→    33→-   Roll back to the previous known-good certificate/configuration if
    34→    34→    deployment fails.
    35→    35→-   Maintain detailed audit logs for every automated and manual
    36→    36→    operation.
    37→    37→
    38→    38→The product should feel like a professional enterprise DevOps/SaaS
    39→    39→control panel, not a generic hosting panel.
    40→    40→
    41→    41→------------------------------------------------------------------------
    42→    42→
    43→    43→# 2. Core Product Principle
    44→    44→
    45→    45→The application must never blindly trust manually entered expiry dates.
    46→    46→
    47→    47→For every domain:
    48→    48→
    49→    49→1.  User adds domain.
    50→    50→2.  System performs a fresh domain-expiry lookup.
    51→    51→3.  System connects to the live HTTPS endpoint.
    52→    52→4.  System inspects the actual certificate.
    53→    53→5.  System compares discovered values against stored values.
    54→    54→6.  System displays whether the information is verified.
    55→    55→7.  Only after successful verification should automation be enabled by
    56→    56→    default.
    57→    57→8.  Every check must record timestamp, source, result, and errors.
    58→    58→
    59→    59→Example:
    60→    60→
    61→    61→``` text
    62→    62→example.com
    63→    63→
    64→    64→Domain expiry:
    65→    65→RDAP              2027-02-15
    66→    66→Registrar API      2027-02-15
    67→    67→Stored value       2027-01-15
    68→    68→
    69→    69→Status:
    70→    70→⚠ DATE MISMATCH
    71→    71→
    72→    72→SSL expiry:
    73→    73→Live certificate  2026-10-30
    74→    74→Stored value       2026-10-30
    75→    75→
    76→    76→Status:
    77→    77→✓ VERIFIED
    78→    78→```
    79→    79→

    98→    98→
    99→    99→## Backend
   100→   100→
   101→   101→-   Next.js server/API routes where appropriate
   102→   102→-   Node.js/TypeScript service layer
   103→   103→-   Prisma ORM
   104→   104→-   PostgreSQL
   105→   105→
   106→   106→## Background Processing

   108→   108→Use:
   109→   109→

   221→   221→# 6. Visual Design System
   222→   222→
   223→   223→## Design direction
   224→   224→
   225→   225→Create a clean, modern, high-fidelity enterprise SaaS interface.
   226→   226→
   227→   227→Characteristics:
   228→   228→
   229→   229→-   White/light gray primary surfaces.
   230→   230→-   Very subtle borders.
   231→   231→-   Rounded cards.
   232→   232→-   Strong visual hierarchy.
   233→   233→-   Compact but readable tables.
   234→   234→-   Blue primary action color.
   235→   235→-   Green for healthy/success.
   236→   236→-   Amber for warning/expiring.
   237→   237→-   Red for critical/expired/error.
   238→   238→-   Purple can be used for infrastructure/server-related metrics.
   239→   239→-   Avoid excessive gradients.
   240→   240→-   Avoid oversized decorative elements.
   241→   241→-   Use icons to reinforce status.
   242→   242→-   Use whitespace generously.
   243→   243→-   Prioritize information density without clutter.

   939→   939→# 15. Automatic SSL Renewal Workflow
   940→   940→
   941→   941→The worker should implement:
   942→   942→
   943→   943→``` text
   944→   944→Check certificate
   945→   945→        ↓
   946→   946→Days remaining <= renewal threshold?
   947→   947→        ↓
   948→   948→Request ACME renewal
   949→   949→        ↓
   950→   950→Perform validation
   951→   951→        ↓
   952→   952→Receive certificate
   953→   953→        ↓
   954→   954→Backup current certificate
   955→   955→        ↓
   956→   956→Install new certificate
   957→   957→        ↓
   958→   958→Test Nginx/Apache configuration
   959→   959→        ↓
   960→   960→Reload server
   961→   961→        ↓
   962→   962→Perform live HTTPS verification
   963→   963→        ↓
   964→   964→Success?
   965→   965→   /          \
   966→   966→ YES           NO
   967→   967→ ↓             ↓
   968→   968→Complete     Rollback
   969→   969→                ↓
   970→   970→             Alert
   971→   971→```
   972→   972→
   973→   973→Use a renewal threshold such as 30 days by default, while retaining the
   974→   974→mandatory 5-day alert.
   975→   975→
   976→   976→Do not wait until 5 days before starting renewal.

  1609→  1609→# 32. Security Requirements
  1610→  1610→
  1611→  1611→This is a security-sensitive application because it may control
  1612→  1612→production servers.
  1613→  1613→
  1614→  1614→Implement:
  1615→  1615→
  1616→  1616→-   Strong authentication.
  1617→  1617→-   Password hashing with Argon2id or equivalent.
  1618→  1618→-   Optional/required 2FA for privileged users.
  1619→  1619→-   Role-based access control.
  1620→  1620→-   Secure HTTP-only cookies.
  1621→  1621→-   CSRF protection where applicable.
  1622→  1622→-   Strict CORS configuration.
  1623→  1623→-   Rate limiting.
  1624→  1624→-   Input validation with Zod.
  1625→  1625→-   SQL injection protection through Prisma.
  1626→  1626→-   XSS protection.
  1627→  1627→-   Content Security Policy.
  1628→  1628→-   HSTS.
  1629→  1629→-   Secure headers.
  1630→  1630→-   Encryption at rest for credentials.
  1631→  1631→-   Secrets stored outside source code.
  1632→  1632→-   Audit logging.
  1633→  1633→-   SSH host-key verification.
  1634→  1634→-   No arbitrary shell commands from user input.
